# Open a Pull Request for Boilerplate Drift

## Context and Problem Statement

`.gitignore` is generated by Cobo from upstream github/gitignore templates
recorded in `cobo.lock`. A weekly check that only *reports* drift leaves a
person to regenerate and commit; in practice the chore sits until someone
trips over it.

## Considered Options

* Report drift only: a failing weekly run, fixed by hand
* Open a pull request with the pinned `hasansezertasan/cobo` action
* Drop the workflow and rely on Renovate and manual `cobo sync`

## Decision Outcome

Chosen option: "Open a pull request." `gitignore-drift.yml` runs weekly
(Monday 07:00 UTC, ahead of the manifest updates) and on demand, re-renders
via the pinned `hasansezertasan/cobo` action, and pushes a
`chore/sync-cobo-boilerplate` branch with a pull
request. It passes `token: ${{ secrets.WORKFLOW_TOKEN || secrets.GITHUB_TOKEN }}`
so the pull request's checks start by themselves when the secret is configured
(see [ADR-0007](0007-optional-workflow-token-for-automated-pull-requests.md)),
and `fail-on-sync-error: "true"` so an unreachable template fails the run
instead of leaving no diff and a green build.

### Consequences

* Good, because upstream template fixes arrive reviewable instead of nagging.
* Good, because the branch name already satisfies `check-branch-name.yml`.
* Bad, because the pull request opened with the `GITHUB_TOKEN` fallback needs
  its checks approved or re-triggered by hand.
